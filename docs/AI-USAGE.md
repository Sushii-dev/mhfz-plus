# AI usage

MHFZ Plus is a collaboration between a person and an AI coding agent. We say so up front so that everyone can decide
for themselves how to treat it.

## Who did what

**The maintainer ([Sushii-dev](https://github.com/Sushii-dev)) led the project:**

- **Research.** Studied how the game, its servers and the community tools work before any code existed: the
  reverse-engineering approach, the client's protections, Rain's launcher and file checks, and the existing projects
  this builds on.
- **Direction and rules.** Chose what to build and set the rules every change had to meet: no added input latency,
  never slow the game's 30 Hz tick, never patch game code, stay low-profile. Turned down shortcuts that broke them,
  such as extra frames bought with latency.
- **Structure and process.** Designed how the work was organised: overnight build rounds with a morning report and a
  test protocol, glitch reports backed by recorded clips, a validation gate before every build reached the game, and
  the release package for other players. The launcher's Rain mode, which puts files in after the launcher's check,
  comes from the maintainer's earlier English-translation project.
- **Prompt engineering.** Wrote the briefs that steered the agent: the goals of each round, the constraints, what
  counted as done, and when to stop and rethink.
- **Testing and diagnosis in the game.** Played every candidate build for many hours, recorded the clips most fixes
  started from, and narrowed problems down. For example:
  - found that the character flicker was the "realistic shadows" setting dropping out, by toggling it;
  - found that the light flicker only happened within a few metres of two or more lamps;
  - made the last tree flicker reproducible by flicking the camera hard at one distant tree.
- **Decisions.** Decided what shipped, accepted the ~150 fps ceiling rather than trade latency for it, and chose the
  license and how the project is published.

**The AI (Anthropic's Claude, through the Claude Code agent)** did the implementation under that direction:

- the static analysis of the game's renderer and frame limiter (with Ghidra and Python scripts);
- nearly all of the code: the frame-rate mod (`src/`), the launcher, the installer scripts and the settings app;
- the test app, the offline benches and the analysis tools;
- most of the documentation, this page included, reviewed by the maintainer.

**The English translation** (the optional part of the launcher) was machine-translated, a first pass with Qwen and
then Gemma, followed by automated review passes. No human translator checked it line by line, so expect odd lines.

## What this means for you

- **Review it like any other code.** The mod has a large test setup (see [TESTING.md](TESTING.md)) and many hours of
  real play, but few human experts have read the code. Read it before you trust it, and please report problems.
- **The design notes say where things were measured and where they're guesses.** [ENGINE-NOTES.md](ENGINE-NOTES.md)
  marks unconfirmed points as believed or unknown.
- **Copyright.** In some countries, material generated by AI may have limited copyright protection, even when a
  person directed it. The license grants whatever rights the maintainer has; it doesn't claim more.
- **No copied code.** Nothing from Capcom, and no code from other projects was pasted in. Anything this builds on is
  listed in [CREDITS.md](CREDITS.md).

## Contributions

Contributions written with AI help are welcome, the same as any others. Say in the pull request that AI was used and
how you tested the change. In-game testing matters more than how the code was written.
